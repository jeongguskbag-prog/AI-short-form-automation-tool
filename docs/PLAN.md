# 쇼핑 쇼츠 자동화 앱 기획서

> 제품 키워드 하나로 **아이템 찾기 → 소재 모으기 → 대본·음성 → 자동 편집·썸네일 → 5개 플랫폼 배포**까지
> 5분 안에 끝내는 쇼핑 쇼츠 제작 도구.
> 참고: '루시' 자동화 프로그램(자판기) 소개 영상. 이 문서는 그 흐름을 이 저장소의 현재 코드 위에 어떻게 올릴지 정리합니다.

---

## 1. 목표와 대상

| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 촬영·편집 없이 제휴 마케팅(쿠팡 파트너스 등)용 쇼핑 쇼츠를 만들고 여러 플랫폼에 한 번에 올리는 도구 |
| 주 사용자 | 부업으로 제휴 마케팅을 하려는 초보자 (60~70대 포함). 편집 프로그램을 써 본 적 없는 사람 |
| 핵심 가치 | ① 무엇을 팔지 고르기 쉽게 ② 영상 1편 5분 이내 ③ 버튼 한 번으로 5개 플랫폼 배포 |
| 쓰는 환경 | PC 웹 브라우저 우선, 휴대폰 브라우저(안드로이드 Termux 포함)에서도 동작 |

### 설계 원칙

1. **큰 글씨, 단계 하나씩.** 화면마다 해야 할 일은 하나, 버튼은 크게, 다음 단계는 항상 오른쪽 아래 같은 자리.
2. **기본값으로 끝까지 간다.** 키워드만 넣고 "다음"만 눌러도 업로드 직전까지 완성돼야 한다. 고치고 싶은 사람만 고친다.
3. **올려도 문제없는 영상만 만든다.** 저작권·광고 표시·플랫폼 정책을 앱이 대신 챙긴다 (7장).

## 2. 사용자 흐름

```
① 아이템 찾기 ─▶ ② 소재 모으기 ─▶ ③ 대본·음성 ─▶ ④ 자동 편집·썸네일 ─▶ ⑤ 다중 플랫폼 배포
  카테고리/키워드     프로젝트 '장바구니'     AI 대본 + TTS        단어 단위 컷 편집        유튜브·인스타·틱톡
  인기 순 정렬        영상·사진 담기         자막 자동           AI 제목·썸네일         페이스북·스레드
```

### ① 아이템 찾기

> 영상 시연 화면(12:15~12:54) 캡처를 보고 구성을 맞췄습니다.

**필터 바** (한 줄, 왼쪽부터)

| 항목 | 형태 | 값 |
|---|---|---|
| 분야 | 드롭다운 | 전체 분야 · 생활·가전·인테리어 · 주방 · 뷰티 · 디지털 · 패션 · 육아 · 반려동물 |
| 기간 | 4칸 버튼 | 1개월 · 3개월 · 6개월 · 1년 (게시일 기준) |
| 정렬 | 드롭다운 | **성과순**(기본) · 조회수순 · 좋아요순 · 댓글순 · 최신순 |
| 검색어 | 입력창 | 상품명·해시태그·작성자. 안내 문구: "상품명·해시태그·작성자·공개 댓글에서 찾습니다. 즐겨찾기는 검색 조건과 관계없이 맨 앞에 표시합니다." |

- **성과순** = 조회수 ÷ 채널 구독자 수. 구독자가 적은데 조회수가 터진 영상일수록 위로 올라옵니다
  (채널 인기가 아니라 **제품·후킹이 먹힌 영상**을 찾기 위함). 카드 왼쪽 위에 배지로 `x412`처럼 배수를 표시합니다.
- 영상 시연의 사용 흐름: 분야 "주방" → 정렬 "댓글순"으로 바꿔 구매 문의 댓글이 많은 영상을 찾습니다.
- **즐겨찾기**한 영상은 어떤 조건에서든 맨 앞에 고정합니다.

**결과 요약 줄** (필터 바 아래, 목록 위)

```
성과순 · 2026-09-22 05:43 기준 (수집 2026-09-22 05:54)
즐겨찾기 1개 유지 · 성과순 기준 값이 있는 61개 먼저 · 구독자·조회수를 알 수 없는 7개는 뒤에 표시 · 기간 밖 315개 제외
```

- 데이터가 **언제 기준인지**(지표 시각, 수집 시각)를 항상 보여 줍니다.
- 정렬 기준 값이 없는 영상(구독자 수 비공개 등)은 빼지 않고 **뒤로 보냅니다**. 몇 개가 왜 뒤로 갔는지, 기간 밖이라 몇 개가 빠졌는지 숫자로 알려 줍니다.

**결과 카드** (세로 영상 썸네일 그리드)

- 썸네일, 성과 배지(`x412`), 조회수·좋아요·댓글 수, 게시일, 채널 이름, 즐겨찾기 별, "이 제품으로 만들기" 버튼.
- 카드를 열면 "왜 뜨는지" AI 한 줄 분석(후킹 문장 유형, 길이, 첫 3초 구성)과 제품명 추정.

**왼쪽 메뉴** (아이콘 + 짧은 이름): 아이템 찾기 · 제작 · 보관함 · 배포 · 설정

**데이터 수집**

- YouTube Data API: `search.list`(분야별 검색어, 쇼츠 길이, 기간) → `videos.list`(조회수·좋아요·댓글 수) →
  `channels.list`(구독자 수, 비공개면 "알 수 없음").
- 공개 댓글 검색은 `commentThreads.list`로 **상위 후보에만** 수집합니다 (할당량 절약).
- 사용자가 누를 때마다 API를 부르지 않고, **정해진 시각에 한 번 수집해 저장**한 뒤 화면은 저장본으로 필터·정렬합니다.
  그래서 요약 줄에 기준 시각이 붙습니다.
- 다른 플랫폼은 공식 API가 없거나 막혀 있어 1차 범위에서 제외합니다.
- **분석은 메타데이터만** 씁니다. 남의 영상을 내려받지 않습니다 (7장).

### ② 소재 모으기 (프로젝트 '장바구니')

카드에서 "이 제품으로 만들기"를 누르면 프로젝트가 생기고, 소재를 장바구니처럼 담습니다.

| 소재 출처 | 설명 | 단계 |
|---|---|---|
| 내 영상·사진 업로드 | 휴대폰으로 찍은 언박싱, 판매자에게 받은 영상 등 | MVP |
| 무료 스톡 **영상** | Pexels·Pixabay 비디오 API (지금은 사진만 지원 → 영상으로 확장) | MVP |
| 무료 스톡 사진 | Pexels·Pixabay·Openverse (이미 구현) | 구현됨 |
| AI 이미지 | Gemini 이미지 모델 (이미 구현, 결제 필요) | 구현됨 |
| 판매처 상품 이미지 | 제휴 프로그램이 이용을 허락한 상품 이미지 (쿠팡 파트너스 API 등) | 2단계 |
| AI 영상 | 텍스트/이미지→영상 모델 (비용 검토 후) | 후순위 |

- 각 소재에 **출처와 라이선스**를 함께 저장하고, 업로드 설명란에 출처 표기를 자동으로 넣습니다.
- 소재가 모자라면 앱이 대본의 문장별 검색어로 스톡 영상을 자동으로 채웁니다.

### ③ 대본·음성 자동 생성

- 입력: 제품명, 판매 링크, (선택) 제품 특징 메모, 참고한 인기 영상의 "후킹 유형".
- Gemini가 **15~40초 쇼핑 쇼츠 대본**을 씁니다. 구조 고정: `후킹(3초) → 문제 상황 → 제품 해결 → 핵심 장점 2~3개 → 행동 유도`.
- 후킹 문장 3개를 제안하고 사용자가 고르게 합니다 (기본값은 1번).
- 대본 검사: 과장·허위 표현("무조건", "100% 효과", 의학적 효능 등) 자동 경고, 광고 표시 문구 자동 포함.
- 음성: 지금처럼 Edge TTS. 목소리 3~4종(여/남, 차분/활기) 미리 듣기. 속도 조절.

### ④ 자동 편집·썸네일

- **단어 단위 동기화**: Edge TTS가 주는 단어 경계(WordBoundary) 시각을 받아 문장·단어마다 클립 전환 지점과 자막 타이밍을 정합니다.
- 문장마다 장바구니에서 가장 어울리는 소재를 AI가 골라 배치 (소재 설명 ↔ 문장 의미 매칭). 사용자는 끌어서 바꿀 수 있음.
- 영상 소재는 길이에 맞춰 자르고, 사진은 지금처럼 켄 번스 효과.
- 자막: 핵심 단어 강조색, 화면 중앙 하단, 한 줄 최대 12자 내외.
- 배경음악: 저작권 걱정 없는 무료 음원 목록에서 분위기별 자동 선택, 내레이션 구간에서 자동으로 볼륨 낮춤(덕킹).
- **AI 제목 추천 5개** + **썸네일 3안**(영상 프레임 + 큰 글씨 문구, Pillow로 합성).
- 결과 미리보기 → 문장 단위로 소재 교체·자막 수정 → 다시 렌더링(바뀐 문장만).

### ⑤ 다중 플랫폼 배포

- 플랫폼 계정을 한 번 연결(OAuth)해 두면, 완성 화면에서 체크박스로 고르고 "한 번에 올리기".
- 플랫폼마다 제목·설명·해시태그 글자 수 제한에 맞춰 자동 변환, 판매 링크는 플랫폼별 규칙에 맞는 자리(설명란·고정 댓글·프로필 링크 안내)에.
- 즉시 올리기 / 예약 올리기. 플랫폼별 결과(성공·실패·링크)를 한 화면에서 확인, 실패한 것만 다시 시도.

| 플랫폼 | 공식 API | 미리 알아둘 제약 |
|---|---|---|
| YouTube Shorts | YouTube Data API `videos.insert` | 업로드 1건이 일일 할당량을 크게 차지(기본 할당량으로 하루 몇 건 수준). 앱 심사 전에는 비공개로만 올라갈 수 있음 |
| Instagram Reels | Instagram Graph API (콘텐츠 게시) | 비즈니스/크리에이터 계정 + Meta 앱 심사 필요 |
| Facebook Reels | Facebook Graph API (페이지) | 페이지 계정 필요, Meta 앱 심사 |
| Threads | Threads API | Meta 앱 심사, 영상 게시 지원 범위 확인 필요 |
| TikTok | Content Posting API | 앱 감사(audit) 통과 전에는 비공개 게시만 가능 |

> 각 플랫폼의 정확한 할당량·심사 조건은 구현 시점에 공식 문서로 다시 확인합니다. 심사 통과 전에는
> **"다운로드 + 플랫폼별 설명 문구 복사"** 방식으로 우회 없이 제공합니다.

## 3. 현재 코드에서 이어 가기

지금 저장소는 **대본 → 씬 기획 → TTS + 이미지 → 자막 → 9:16 영상** 파이프라인이 동작합니다 (테스트 43개 통과).
③·④의 뼈대가 이미 있으므로 그 위에 쌓습니다.

| 기능 | 현재 | 해야 할 일 |
|---|---|---|
| 씬 기획 (`services/planner.py`) | 대본 → 씬 JSON | 제품 정보 → 쇼핑 대본 생성 단계 추가, 후킹 3안, 금지 표현 검사 |
| TTS (`services/tts.py`) | Edge TTS 파일 저장 | 단어 경계 시각 함께 저장 → 자막·컷 타이밍에 사용 |
| 이미지 (`services/images.py`) | Gemini → Pexels → Pixabay → Openverse 체인 | 같은 체인 구조로 **영상 소재 소스** 추가, 사용자 업로드 소재 |
| 렌더링 (`services/video.py`) | 사진 + 켄 번스 + 자막 PNG | 영상 클립 자르기·크롭(9:16), 배경음악·덕킹, 단어 강조 자막, 썸네일 |
| 작업 저장 (`jobs.py`) | 프로세스 메모리, 24시간 후 삭제 | SQLite로 프로젝트·소재·업로드 기록 영구 저장 |
| 웹 화면 (`web/index.html`) | 대본 입력 한 화면 | 5단계 마법사 화면 |
| 신규 | — | 트렌드 탐색, 프로젝트/장바구니, 제목·썸네일, 플랫폼 연결·업로드 |

### 새로 생길 모듈

```
app/
  services/
    trends.py        # YouTube Data API로 인기 쇼츠 지표 정기 수집·저장, 성과순(조회수÷구독자) 계산
    scriptwriter.py  # 제품 정보 → 쇼핑 대본(후킹 3안) + 표현 검사
    footage.py       # 스톡 영상 소스 체인 (Pexels/Pixabay 비디오) + 업로드 소재
    matcher.py       # 문장 ↔ 소재 매칭
    thumbnail.py     # 썸네일 3안 합성
    music.py         # 무료 배경음악 선택·덕킹
  publishers/
    base.py          # Publisher 프로토콜: connect / upload / status
    youtube.py  instagram.py  facebook.py  threads.py  tiktok.py
  db.py              # SQLite (프로젝트, 소재, 렌더 결과, 플랫폼 계정, 업로드 기록)
```

`Planner`·`TTSEngine`·`ImageGenerator`처럼 **프로토콜 + 가짜 구현으로 테스트**하는 지금 방식을 그대로 따릅니다.

## 4. 데이터 모델 (SQLite)

| 테이블 | 주요 필드 |
|---|---|
| `trend_videos` | 영상 ID, 분야, 제목·해시태그, 채널, 구독자 수(없으면 NULL), 조회수·좋아요·댓글 수, 게시일, 지표 기준 시각, 수집 시각, 즐겨찾기 |
| `projects` | id, 제품명, 판매 링크, 카테고리, 참고 영상 ID, 상태, 생성일 |
| `assets` | id, project_id, 종류(영상/사진/음악), 파일 경로, **출처, 라이선스, 원작자**, 길이, AI 설명 |
| `scripts` | id, project_id, 후킹 3안, 선택한 대본, 경고 목록 |
| `renders` | id, project_id, 영상 경로, 썸네일 3안, 제목 5안, 길이 |
| `accounts` | id, 플랫폼, 계정 이름, **암호화된** 토큰, 만료일 |
| `publications` | id, render_id, 플랫폼, 상태, 게시 URL, 오류, 예약 시각 |

- OAuth 토큰은 `.env`의 비밀키로 암호화해 저장 (평문 저장 금지).

## 5. API 초안

```
GET  /api/v1/trends?category=kitchen&period=1m&sort=comments&q=...   인기 쇼츠 목록 + 요약(기준 시각, 뒤로 보낸 수, 제외 수)
PUT  /api/v1/trends/{video_id}/favorite                   즐겨찾기
POST /api/v1/projects                                     프로젝트 생성 {product_name, product_url, reference_video_id?}
POST /api/v1/projects/{id}/assets                         소재 업로드 / 스톡 검색 결과 담기
GET  /api/v1/footage/search?q=...                         스톡 영상 검색
POST /api/v1/projects/{id}/script                         대본 생성 (후킹 3안)
POST /api/v1/projects/{id}/render                         렌더 작업 생성 → 기존 status 방식으로 진행률 조회
GET  /api/v1/accounts  /  POST /api/v1/accounts/{platform}/connect   플랫폼 연결
POST /api/v1/renders/{id}/publish {platforms:[...], schedule_at?}    배포
GET  /api/v1/renders/{id}/publications                    플랫폼별 결과
```

기존 `/api/v1/shorts/generate`(대본 → 영상)는 그대로 유지합니다.

## 6. 화면 구성

1. **홈**: "새 쇼츠 만들기" 큰 버튼 + 최근 프로젝트 목록.
2. **아이템 찾기**: 분야·기간·정렬·검색어 필터 바, 결과 요약 줄, 성과 배지가 붙은 세로 카드 그리드 (①단계 참고). 어두운 화면 + 선택된 항목은 형광 초록 테두리.
3. **소재 담기**: 왼쪽 검색/업로드, 오른쪽 장바구니. 하단에 "소재 3개 이상이면 좋아요" 안내.
4. **대본**: 후킹 3안 라디오 버튼, 대본 편집창, 경고 표시, 목소리 미리 듣기.
5. **편집 결과**: 영상 미리보기, 문장별 타임라인(소재 교체), 제목 5안, 썸네일 3안.
6. **배포**: 플랫폼 체크박스, 플랫폼별 설명 미리보기, 즉시/예약, 결과 표.
7. **설정**: API 키, 플랫폼 계정 연결, 기본 목소리·자막 스타일, 광고 표시 문구.

## 7. 저작권·광고·플랫폼 정책 (앱이 대신 챙길 것)

소개 영상의 방식 중 일부는 그대로 따라 하면 **계정 정지나 법적 분쟁**으로 이어질 수 있어, 이 앱은 다르게 설계합니다.

| 영상에서 소개한 방식 | 위험 | 이 앱의 방식 |
|---|---|---|
| 전 세계에서 남의 인기 영상을 찾아 소재로 사용 | 원작자 허락 없는 재사용은 저작권 침해. 유튜브 '재사용 콘텐츠', 틱톡 '독창적이지 않은 콘텐츠' 정책으로 수익 정지·노출 제한 | 인기 영상은 **아이템·후킹 분석용 지표로만** 사용. 소재는 직접 촬영·판매자 제공·상업 이용 가능한 스톡·AI 생성으로 한정 |
| 영상 다운로드 + 텍스트(워터마크) 제거 툴 | 원작자 표시를 지우는 행위 자체가 저작권법상 권리관리정보 제거에 해당할 수 있음 | **만들지 않음.** 대신 내가 찍은 영상의 화면 글자 정리 기능은 2단계 이후 검토 |
| 쿠팡 파트너스 링크 게시 | 공정위 추천·보증 심사지침: 경제적 대가를 받는 게시물은 **눈에 잘 띄게 표시** 의무 | 대본 끝·자막·설명란 첫 줄에 "이 게시물은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다." 자동 삽입 (끌 수 없음, 문구는 수정 가능) |
| AI 음성·AI 이미지 | 유튜브·틱톡은 사실적인 AI 생성 콘텐츠 표시를 요구 | 업로드 시 플랫폼의 AI 표시 항목 자동 체크 |
| 같은 영상 5개 플랫폼 동시 게시 | 플랫폼마다 워터마크 영상·중복 게시를 낮게 평가 | 플랫폼별로 워터마크 없는 원본을 올리고, 제목·설명·해시태그를 다르게 생성 |
| "월 1억" 수익 | 수익은 보장할 수 없음 | 앱 안에서 수익을 약속하는 문구를 쓰지 않음. 성과는 실제 조회수·클릭 데이터로만 보여 줌 |

## 8. 단계별 로드맵

> **진행 상황**
> - ① 아이템 찾기 화면 구현 완료 (`/trends`, `app/services/trends.py`). AI 한 줄 분석(`app/services/trend_analysis.py`)도 완료.
> - ③ 쇼핑 대본 자동 작성 구현 완료 (`app/services/scriptwriter.py`): 후킹 3안, 제목 5안, 해시태그, 설명란,
>   광고 표시 자동 삽입, 과장 표현 경고, 참고 영상 반영. 지금은 기존 영상 만들기 화면 안에 있고, 프로젝트 저장(SQLite)은 아직 없음.
> - ② 내 영상·사진 업로드 구현 완료 (`app/media.py`): 씬마다 순서대로 배경으로 사용, 영상은 9:16 자르기·반복.
>   무료 스톡 영상(Pexels·Pixabay)도 구현 완료 (`app/services/footage.py`). 장면↔소재 AI 배치도 완료 (`app/services/matcher.py`).
> - ④ 썸네일 3안 구현 완료 (`app/services/thumbnail.py`). 제목 5안은 쇼핑 대본에서 제공.
> - ④ 단어 단위 자막 구현 완료 (`app/services/subtitles.py`): Edge TTS 단어 시각으로 구절 자막 + 읽는 단어 강조.
>   단어 시각에 맞춘 **클립 전환**은 아직 없음.
> - ④ 배경음악 구현 완료: 사용자가 올린 음악을 반복·덕킹·페이드아웃으로 합성.
> - ⑤ 배포: 유튜브 업로드 구현 완료 (`app/publishers/youtube.py`, 보관함에서 올리기). 인스타·페이스북·스레드·틱톡은 앱 심사 필요로 아직.
> - 단계별 화면 구현 완료: 영상 만들기 화면을 ② 대본 → ③ 소재·음악 → ④ 완성 단계로 나눔 (① 아이템 찾기는 `/trends`, ⑤ 배포는 준비 중).
> - 보관함(프로젝트 저장) 구현 완료 (`app/projects.py`, `/library`): 완성 영상·썸네일·대본·설명란·제목 후보를 SQLite에 30일 보관.

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| **1. MVP** (2~3주) | 제품 정보 → 쇼핑 대본(후킹 3안) → 업로드·스톡 영상 소재 → 단어 동기 편집 → 제목 5안·썸네일 3안 → 다운로드 + 플랫폼별 설명 복사. 광고 표시 자동 삽입. SQLite 프로젝트 저장 | 키워드와 판매 링크만으로 5분 안에 업로드 가능한 영상과 썸네일·설명이 나온다 |
| **2. 아이템 찾기** (1~2주) | YouTube Data API 트렌드 탐색, 카테고리·정렬, AI 한 줄 분석, 프로젝트 장바구니 화면 | 카테고리 선택 → 댓글 순 인기 제품 목록 → 프로젝트 생성까지 화면에서 된다 |
| **3. 자동 배포** (3~4주, 심사 기간 별도) | YouTube → Instagram/Facebook → Threads → TikTok 순으로 연결·업로드, 예약, 실패 재시도 | 연결된 플랫폼에 버튼 한 번으로 올라가고 결과 링크가 보인다 |
| **4. 성과** | 플랫폼별 조회수·클릭 수 수집, 잘된 후킹 유형을 다음 대본 생성에 반영 | 대시보드에서 영상별 성과 비교 |

### MVP 작업 목록 (순서대로)

1. `db.py` + 프로젝트/소재 테이블, 기존 `JobStore`와 연결
2. `footage.py`: Pexels·Pixabay 비디오 검색 (지금 사진 체인 구조 재사용), 업로드 소재 API
3. `video.py`: 영상 클립 자르기·9:16 크롭, 배경음악 덕킹
4. `tts.py`: 단어 경계 저장 → 단어 강조 자막
5. `scriptwriter.py`: 쇼핑 대본 + 후킹 3안 + 표현 검사 + 광고 표시
6. `matcher.py`: 문장 ↔ 소재 매칭
7. `thumbnail.py` + 제목 5안
8. 웹 화면 5단계 마법사 (1단계 '아이템 찾기'는 키워드 입력만)
9. 테스트: 가짜 공급자로 전 과정 렌더링 검증 (지금 방식 유지)

## 10. 결정이 필요한 것

1. **제휴 프로그램 범위**: 쿠팡 파트너스만? 네이버 쇼핑 커넥트, 알리 어필리에이트 등도? (링크 형식·광고 문구가 다름)
2. **배포 형태**: 지금처럼 각자 설치형(PC/Termux)으로 갈지, 여러 사람이 쓰는 웹 서비스로 갈지.
   웹 서비스라면 회원·결제·플랫폼 앱 심사를 앱 운영자 명의로 받아야 합니다.
3. **비용**: Gemini 이미지·영상 모델은 유료. 무료(스톡+Edge TTS)만으로 MVP를 끝낼지.
4. **트렌드 데이터**: YouTube 외 플랫폼은 공식 API가 없어 1차 제외 — 이대로 괜찮은지.
